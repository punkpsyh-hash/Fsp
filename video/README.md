## Повторный рендер

Из корня репозитория, нужен Docker с Linux containers:

```bash
docker build -f video/Dockerfile -t fsp-demo-video .
docker run --rm --network none --shm-size=1g \
  -v "$PWD/docs/delivery:/out" fsp-demo-video
```

В PowerShell используйте `${PWD}` и вводите команды одной строкой.
В Git Bash на Windows заранее выполните `export MSYS_NO_PATHCONV=1`.
Рендер использует два параллельных процесса; время зависит от CPU и диска.
Сборка скачивает зависимости из npm и образ Playwright; сам рендер работает
без сети. Веса модели и работающий сервер приложения для монтажа не нужны.
Для просмотра композиции до рендера:

```bash
docker run --rm -p 127.0.0.1:3307:3307 fsp-demo-video npm run studio
```

Откройте `http://127.0.0.1:3307/FspDemo`. Предпросмотр остановится после Ctrl+C.
Файл результата перезаписывается; сохраните свою версию перед повторным рендером.

`storyboard.json` хранит исходные интервалы и проверенные тексты.
Чтобы пересобрать JSX, SRT/VTT и таймкоды после правки:

```bash
docker run --rm --network none --entrypoint python3 \
  -v "$PWD:/repo" -w /repo fsp-demo-video video/generate.py
docker build -f video/Dockerfile -t fsp-demo-video .
```

Все клипы и подписи представлены отдельными JSX-узлами в `src/Root.tsx`.
Анимации вычисляются по номеру кадра; субтитры и видео используют общий trim
в родительской секвенции. Частота исходной записи и рендера одинакова.
Для быстрого последовательного рендера Docker извлекает исходные кадры
в PNG без потерь. Эти промежуточные файлы остаются внутри образа и не входят
в Git; имена кадров сопоставляются с исходными номерами и подписями.
