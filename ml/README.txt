Рабочая область локальных моделей. Подготовлена 9 октября 2026.

models/ — веса базовых моделей; adapters/ — LoRA-адаптеры;
runs/ — логи и результаты экспериментов; datasets/raw/ — исходные данные;
datasets/curated/ — проверенные задания; datasets/splits/ — train/validation/test.
Эти каталоги исключены из Git. Базовые веса, split и первый адаптер установлены
локально на D; результаты пилота — docs/llm-pilot-results.json.

Перед выбором модели проверить видеокарту, VRAM и доступную RAM на Windows.
В контейнере API адрес модели на Windows задаётся через host.docker.internal.
FSP_LLM_* задаются в локальной .env; compose.yaml передаёт их только в app.
Не переносить NAS-IP в конфигурацию ПК. Значение по умолчанию — none;
наличие настроек не означает, что модель установлена или её качество проверено.

Для дообучения потребуется отдельно собрать и проверить русскоязычные задания,
эталонные ответы и рубрики. Разделять выборки по семействам, а не случайно по
близким вариантам одного задания; выделять независимую контрольную выборку.
Текущие синтетические тестовые отчёты не являются готовым обучающим датасетом.
Первый этап — сравнить базовые модели без обучения на одинаковой проверенной
выборке: правильность ответа, однозначность, сложность, время и потребление VRAM.

Генерация предлагает черновик автору. Первичную оценку грейда и опубликованные
версии не заменять непроверенным выходом модели. Для code проверять эталон
в существующей одноразовой QEMU VM, не запускать модельный код в API/на хосте.

Первый программный срез: src/server/bank_generation.py создаёт только один
приватный черновик single_choice, multiple_choice, numeric или open_response.
Ответ модели обязан быть JSON-объектом и пройти схему конструктора и проверку
полей публикации. Код и эталоны для исполнения пока не генерируются. Схема
не доказывает правильность ключа, рубрики или равную сложность; автор должен
проверить содержание перед отдельным сохранением и публикацией. Mock — явно
демонстрационный образец, не обученная модель.

Свободный текст работодателя для генерации передаётся только выбранному
локальному/внутреннему серверу модели, в том числе если URL использует HTTPS.
`redact()` убирает отдельные типичные контакты, но не является полным
обезличиванием: имя, организация или редкий идентификатор могут остаться.
Существующий облачный режим объяснения подборки регулируется отдельно;
генератор заданий его не наследует.

Перед дообучением нужен частный корпус с происхождением и правами каждого
примера, проверенным человеком ключом/рубрикой, нормализованным запросом автора
и семейством задания. Нельзя автоматически считать 13 задач из двух JSON-банков
обучающей выборкой: это примеры продукта и повторяющиеся идеи. Близкие варианты
одного семейства должны оставаться в одном split; контрольные семейства не
попадают в обучение и подбор гиперпараметров. Не сохранять ПДн в Git.

Измеряемый порядок: на одинаковой закрытой выборке получить baseline базовой
модели; в отдельном контейнере и с ограничениями ресурсов провести только
поддерживаемое оборудованием дообучение адаптера; записать хеши базовых весов,
датасета и splits, параметры, время, пик VRAM, ошибки и хеш адаптера; повторить
оценку на том же закрытом наборе. Считать машинную валидность JSON и схемы,
экспертную правильность эталона/однозначность/сложность, долю принятых автором
черновиков и задержку. Сравнение с baseline обязательно; даже улучшение метрик
не превращает задания в откалиброванный глобальный тест.

Технический пилот на этом ПК: ml/pilot.py. Открытый checkpoint
Qwen/Qwen2.5-0.5B-Instruct закреплён коммитом
7ae557604adf67be50417f59c2c2f167def9a775, лицензия Apache-2.0:
https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct . Зависимости закреплены в
ml/requirements-pilot.txt, включая torch==2.7.1+cu128 из официального индекса.
Команды подготовки, загрузки, обучения и сравнения выполняются в GPU-контейнере
с монтированными на D каталогами модели/адаптера/данных/результатов, окружения
и HF_HOME/PIP_CACHE_DIR/TMPDIR. Пакеты API не меняются, кэш на C не создаётся.

Запускать с Windows PowerShell из корня проекта через
`scripts/run-llm-pilot.ps1`. Он использует только локальный Docker-образ
`hermes-dashboard-fastapi:latest` (`--pull never`), без Python на хосте.
Проект определяется по расположению скрипта; параметры ProjectPath, CachePath
и LogDirectory позволяют явно задать другие пути. По умолчанию кэш —
`D:/Codex/Caches/fsp-llm`, каждый лог и JSON-квитанция — отдельные файлы в
`local-data/llm-pilot/` проекта, вне Git. Существующие результаты не
перезаписываются. Контейнеру заданы GPU, 8 CPU, 12 GiB RAM, read-only root,
cap_drop ALL и сеть none. Только шаг с `-Online` получает обычную сеть.
Корень проекта монтируется только на чтение; каталоги ml/models, adapters,
runs и datasets монтируются отдельно для записи. PYTHONPATH содержит
`/cache/site-packages` (ранее установленный Torch на D) и `/workspace/Fsp`
(модули проекта); venv добавляет собственные site-packages автоматически.
TMPDIR, HF_HOME и PIP_CACHE_DIR указывают на D-монтированный `/cache`.

Если готового `/cache/pilot-venv` нет, создать его командами помощника:

    & .\scripts\run-llm-pilot.ps1 -Step setup-venv -Interpreter /usr/local/bin/python3 -PythonArguments @('-m','venv','--copies','--system-site-packages','/cache/pilot-venv')
    & .\scripts\run-llm-pilot.ps1 -Step link-torch -Interpreter /usr/local/bin/python3 -PythonArguments @('-c',"from pathlib import Path; Path('/cache/pilot-venv/lib/python3.12/site-packages/local-torch.pth').write_text('/cache/site-packages\n')")
    & .\scripts\run-llm-pilot.ps1 -Step check-torch -PythonArguments @('-m','pip','show','torch')
    & .\scripts\run-llm-pilot.ps1 -Step install-pilot -Online -PythonArguments @('-m','pip','install','--upgrade-strategy','only-if-needed','-r','ml/requirements-pilot.txt')
    & .\scripts\run-llm-pilot.ps1 -Step check-deps -PythonArguments @('-m','pip','check')

`check-torch` должен показать 2.7.1+cu128. Здесь использован обычный pip
в venv на D. Повторный `pip --target` ранее не увидел установленный Torch и
попытался загрузить 2.14; тот setup-контейнер был остановлен до установки.

Для нового запуска задайте уникальное имя, чтобы не перезаписать предыдущие
split, оценки и адаптер. Пример PowerShell (для fetch сеть включена явно):

    $name = 'pilot-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
    $split = "ml/datasets/splits/$name"
    $model = 'ml/models/qwen2.5-0.5b-instruct'
    $budget = "ml/runs/$name-budget.json"
    $base = "ml/runs/$name-base.json"
    $adapter = "ml/adapters/$name"
    $adapted = "ml/runs/$name-adapter.json"
    $comparison = "ml/runs/$name-comparison.json"
    & .\scripts\run-llm-pilot.ps1 -Step prepare -PythonArguments @('ml/pilot.py','prepare','--output',$split)
    & .\scripts\run-llm-pilot.ps1 -Step fetch -Online -PythonArguments @('ml/pilot.py','fetch','--output',$model)
    & .\scripts\run-llm-pilot.ps1 -Step probe -PythonArguments @('ml/pilot.py','probe','--splits',$split,'--model',$model,'--max-length','512','--output',$budget)
    & .\scripts\run-llm-pilot.ps1 -Step base -PythonArguments @('ml/pilot.py','eval','--splits',$split,'--model',$model,'--output',$base)
    & .\scripts\run-llm-pilot.ps1 -Step train -PythonArguments @('ml/pilot.py','train','--splits',$split,'--model',$model,'--max-length','512','--budget-report',$budget,'--base-report',$base,'--output',$adapter)
    & .\scripts\run-llm-pilot.ps1 -Step adapter -PythonArguments @('ml/pilot.py','eval','--splits',$split,'--model',$model,'--adapter',$adapter,'--output',$adapted)
    & .\scripts\run-llm-pilot.ps1 -Step compare -PythonArguments @('ml/pilot.py','compare','--base',$base,'--adapted',$adapted,'--output',$comparison)

Уже загруженная модель не принимает повторный fetch в тот же непустой каталог:
в этом случае пропустите fetch после проверки её локального манифеста.
Порядок фиксирует контрольную выборку до обучения, измеряет полный токенный
бюджет, записывает baseline и только потом обучает адаптер. `train` требует
совпадающих хешей baseline и отчёта probe; при переполнении 512 токенов данные
не обрезаются, допустим новый запуск probe/train с 768 или 1024 после оценки VRAM.

`prepare` фиксирует 4 простых авторских задания для train и 3 конкурсных
семейства для закрытого holdout; code-задания исключены. Исходные рубрики
сохраняются в банке; для учебного JSON одна открытая рубрика получает явные
якоря 0/100, что фиксируется манифестом. В нём также записаны
происхождение, хеши и статус `author_example_not_expert_curated`. Это слишком
мало для продуктового вывода. `probe` измеряет длину всех исходных примеров
полным токенизатором; если train не помещается в 512, допустим отдельный
эксперимент с 768 или 1024 после проверки VRAM. `train` использует LoRA rank 8,
fp16, batch 1 и 20 шагов, контролирует свободную VRAM, не читает holdout и не
обрезает эталоны. Для старта требуется базовая оценка и отчёт о длинах с теми
же хешами. `eval` проверяет строгий JSON, схему,
поля публикации и внутреннюю согласованность ключей/рубрики. Сырые ответы и
результаты остаются локально в исключённом из Git каталоге runs/.
