# Локальный сервис модели для черновиков заданий

> **Быстрый старт и пакет обучения.** Развёртывание модели «с нуля» (скачивание весов, Docker-образ, `compose.llm.yaml`) — [docs/44](../docs/44-deployment-and-operations.md). Корпус, манифесты, отчёты и ссылка на адаптеры — `ml/release/`, описание — [docs/45](../docs/45-ai-answer-check-and-training-package.md). Ниже — актуальная инструкция для Windows-хоста.

Сервис `ml.local_model` использует [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), закреплённую
коммитом `cdbee75f17c01a7cc42f958dc650907174af0554`. Веса загружаются
в 4-битном NF4-режиме на CUDA:0 без переноса слоёв на CPU или диск. Он принимает только
запрос одного из четырёх неисполняемых типов, ограничивает вывод JSON-схемой и
возвращает результат в существующий валидатор конструктора. Ответ модели не
сохраняется и не публикуется автоматически. Схема не подтверждает правильность
ключа или рубрики: автор проверяет содержание перед добавлением черновика.

## Версии схемы на 11 октября 2026

Текущий продуктовый путь после `e0a20e1` использует **serving-v4**. Для
мультивыбора модель возвращает строки `correct_options` (2–4) и
`incorrect_options` (1–2), после чего сервер объединяет и перемешивает варианты,
назначает идентификаторы и вычисляет ключ. Ограничения: условие до 800, рубрика до
400, `solution` до 700 символов, вывод до 1 280 токенов и время сервиса до 120 секунд;
лимит RAM не менялся.

`task_json_schema`, сообщения корпуса с `serving=False` и
`release/datasets/sft-v5.tar.gz` намеренно оставлены в архивном формате
**serving-v3**. Корпус v5 воспроизводит прежнее обучение и не калибрует serving-v4.
Адаптеры v1/v2 отклонены и не активны; по умолчанию используется базовая модель и
профиль `base`. `eval_adapter.py` проверяет продуктовый путь с `serving=True` и
пишет `generation_schema` в отчёт.

Целевая проверка патча дала 100 passed на SQLite за 19,07 с и 100 на PostgreSQL
за 17,73 с: API, корпус и evaluation с полным fake-провайдером плюс реальные
проверки LM Format Enforcer для четырёх схем. Windows helper текущего образа
достиг `ready` за 203,446 с. Финальная живая генерация структурно приняла 4/4
типа за 49,853 / 34,010 / 17,458 / 82,748 с; начальные 2/4 относятся к состоянию
до `e0a20e1`. Ручная сверка подтвердила три закрытых ключа и нашла опечатку в
открытой рубрике, поэтому результат модели всё равно требует редактуры автора.
GPU-проверка подсказки оценки завершилась 16/16 валидными ответами без ошибок:
все четыре группы сохранили strong > partial > wrong и заданные пороги, простая
инъекция не подняла оценку выше wrong + 20. Набор авторский синтетический и не
заменяет экспертную калибровку; отчёт —
[протокол проверки](https://github.com/punkpsyh-hash/Fsp-private-history/blob/22b4a013f4ee5ed4fb93a8d538a8571d0b50fdf0/docs/release/2026-10-11/gpu-review-final.json).
Подробности — [docs/39](https://github.com/punkpsyh-hash/Fsp-private-history/blob/22b4a013f4ee5ed4fb93a8d538a8571d0b50fdf0/docs/39-llm-generation-quality-and-requirements.md),
сводная приёмка — [docs/48](../docs/48-release-acceptance.md).

Веса загружаются только из локального каталога без ссылок. Отдельный manifest
содержит `model_id`, полный `revision` и SHA-256 **каждого** файла модели.
Сервис проверяет manifest до загрузки в GPU и отклоняет лишние файлы, ссылки и
изменённые хеши. Для текущего запуска ожидаются:

```text
ml/models/qwen3-4b-instruct-2507-serving-v3/
ml/release/model-serving-v3-manifest.json
```

Команды из PowerShell в корне проекта:

```powershell
& .\scripts\run-local-model.ps1 start
& .\scripts\run-local-model.ps1 status
& .\scripts\run-local-model.ps1 stop
```

`start` собирает собственный образ `fsp-model` из `docker/model.Dockerfile`.
Первая сборка требует сети для закреплённого базового образа и Python-пакетов;
последующие сборки используют Docker-кэш. Веса нужно получить заранее по
инструкции docs/44. Приватный образ другого проекта и готовый `pilot-venv`
больше не требуются. Проект, кэш GPU, каталог модели и manifest находятся на D.
Python работает внутри образа модели; Python/Node на Windows для запуска не нужны.

Скрипт монтирует веса и manifest только для чтения, кэш GPU отдельно на запись, выдаёт
контейнеру GPU, максимум 8 CPU, 12 GiB RAM и 256 процессов. Root filesystem
только для чтения, временные файлы — в RAM `/tmp`; дочерние привилегии и
capabilities запрещены. Hugging Face и Transformers работают offline.
Контейнер подключён к частной Docker-сети `--internal`; HTTP доступен только
контейнерам этой сети. Порты на хосте не публикуются. Логи Docker
выключены, чтобы не записывать свободный текст запроса. `status` показывает
готовность через `/health`; `stop` проверяет метку и останавливает только
контейнер именно этой рабочей копии. Частная сеть остаётся для повторного
запуска и не затрагивает другие контейнеры.

При необходимости перед `start` задайте ключ только в окружении PowerShell:

```powershell
$env:FSP_LOCAL_MODEL_API_KEY = '<локальный секрет>'
& .\scripts\run-local-model.ps1 start
```

Значение передаётся Docker через имя переменной, не через аргумент с ключом.
Для вызывающего API на этом же Windows-хосте подключите его контейнер к сети,
которую возвращает `start`/`status`, и настройте локальную `.env`:

```text
FSP_LLM_PROVIDER=openai-compatible
FSP_LLM_MODEL=Qwen/Qwen3-4B-Instruct-2507
FSP_LLM_BASE_URL=http://<container из start>:8001/v1
FSP_LLM_TIMEOUT=60
FSP_LLM_API_KEY=<тот же локальный секрет, если включён>
```

Сеть `--internal` на проверенном Docker Desktop не обеспечивает доступ через
опубликованный localhost-порт; проверка выполняется через Docker DNS внутри
сети, а `status` обращается к `/health` внутри контейнера. Эти настройки
рассчитаны на API-контейнер на том же Windows-хосте. Для NAS
понадобится отдельно спроектированное частное соединение; порт модели не
следует публиковать в общедоступной сети. Провайдер продукта остаётся выключенным
по умолчанию: смысловой допуск модели не получен.

Предыдущая Qwen2.5-1.5B-Instruct не прошла разработческие пробы: ответы были
содержательно ошибочными или обрывались. Этот результат не переносится на
Qwen3-4B. Новая модель фактически проверена: 11/12 ответов прошли структуру,
но только 2/12 признаны пригодными без исправлений при независимом техническом
AI-просмотре авторской синтетики. Это не человеческий экспертный пилот.
Ключи, числовые ответы, рубрики и утечки ответа требуют проверки и исправления
автором. Протокол — `docs/local-generation-results.json`. Закрытая выборка уже
использована; изменённую модель или prompt проверяют на новом независимом наборе.

Кэши GPU-компиляции направлены в `D:/Codex/Caches/fsp-llm/gpu-serving`;
веса, основной кэш и проект доступны сервису только для чтения. Вызов реальной
модели через API проверен отдельно: предложение не сохраняет и не публикует банк,
чужая компания получает 404, кандидат — 403. Это локальная проверка API и модели;
она не подтверждает подключение работающего NAS-стенда к Windows.
