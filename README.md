# ФСП · Карьерный профиль

Конкурсная платформа обратного подбора ИТ-специалистов для специального трека
ЛЦТ 2026. Кандидат подтверждает навыки и управляет видимостью профиля.
Работодатель подбирает людей под задачи и получает контакт после согласия кандидата.

[Видео с пояснениями](docs/delivery/demo-explained.mp4) ·
[Презентация PPTX](docs/delivery/fsp-lct-2026.pptx) ·
[Документация](docs/README.md) ·
[Временный стенд жюри](https://fsptest.kolesnikovny.ru)

## Возможности

- Кабинеты кандидата и работодателя, профиль, поиск и объяснение ранжирования,
  приглашения с зарплатой, отклики и переписка.
- Оценка Backend, Frontend, QA и UI/UX для Junior/Middle: серверные версии форм,
  сохранение попыток, повторная проверка и сигналы нарушения правил.
- Конструктор и импорт заданий; практика Python, JavaScript и SQLite
  в одноразовой виртуальной машине через отдельный runner.
- Локальная Qwen для черновиков заданий и рекомендаций по ответам;
  публикация и оценка требуют решения автора.
- API/OpenAPI и локальный mock ФСП ID. Официальный внешний API ФСП не подключён.

## Быстрый запуск

Нужны Docker с Linux containers, Docker Compose v2 и Bash.
Публичный репозиторий скачивается без приглашения и аккаунта GitHub.
Python и Node на хосте для штатного запуска не требуются.

```bash
git clone --branch main --single-branch \
  https://github.com/punkpsyh-hash/Fsp.git fsp
cd fsp
./scripts/run.sh start
./scripts/run.sh status
```

Интерфейс: <http://127.0.0.1:8470>. API: <http://127.0.0.1:8470/api/docs>.
На Windows используйте Git Bash. Подготовка Docker, ресурсы, конфигурация
и устранение ошибок — в [инструкции развёртывания](docs/53-self-deployment.md).

Базовый стенд работает без GPU и модели. Для локального ИИ:

```bash
./scripts/run.sh model-fetch
./scripts/run.sh model-verify
./scripts/run.sh start-llm
./scripts/run.sh check-llm
```

Загружается Qwen3-4B-Instruct-2507 на закреплённой ревизии
`cdbee75f17c01a7cc42f958dc650907174af0554`; файлы проверяются по SHA-256.
Веса не входят в Git. Конфигурация Linux/NVIDIA, Windows и удалённого
совместимого коннектора — в [руководстве эксплуатации](docs/44-deployment-and-operations.md).
Рабочая модель используется без адаптера; результаты экспериментов сохранены
в `ml/release/` и [описании ИИ-контура](docs/45-ai-answer-check-and-training-package.md).

## Проверка и разработка

```bash
./scripts/run.sh test
./scripts/run.sh test-postgres
./scripts/run.sh e2e
./scripts/run.sh verify
./scripts/run.sh report
./scripts/run.sh demo-check
./scripts/run.sh package
```

`report` собирает семь пар PDF/Word из явного списка источников;
`demo-check` проверяет опубликованный MP4; `package` создаёт архив чистого HEAD.
Остановка с сохранением базы: `./scripts/run.sh stop`.
Правила изменений — в [CONTRIBUTING.md](CONTRIBUTING.md).
Версии проверенного кода: [статус](docs/00-status.md),
[приёмка](docs/48-release-acceptance.md).

## Режимы и ограничения

Локальный стенд использует синтетические данные и поддерживает полный
демонстрационный путь. Для внешнего стенда жюри реализована отдельная opt-in
регистрация кандидата или работодателя: пользователь задаёт собственный пароль,
подтверждает согласие и получает сгенерированный логин вида `jury-…@example.invalid`.
Логин нужно сразу скопировать и сохранить: после выхода повторный вход выполняется
с ним и выбранным паролем. Почта, реальные email, импорт резюме и ФСП mock в этом
режиме отключены; модель не подключена. Локальные проверки реализации пройдены,
а v3 активирован на внешнем домене: TLS health возвращает 200, `jury-demo` и
`auth_mode=individual`. Выбранный PostgreSQL-набор прошёл 76/76; это три новых
PG-кейса и 73 адресные API/product/mail-проверки, а не полный серверный набор.
Live browser-матрица прошла шесть потоков: candidate и employer в Chromium,
Firefox и WebKit. Десять негативных HTTPS-проверок также пройдены с обычной
проверкой TLS. Это проверенный конкурсный контур, но не полный pentest и не
полный PostgreSQL-набор проекта.
[Описание временного стенда](docs/61-temporary-domain-stand.md).

Внешняя SMTP-доставка и реальная интеграция ФСП не настроены. Независимый
пилот, экспертная калибровка Junior/Middle и подтверждение качества найма
не проводились. Диагностика защиты проверяет заданные стратегии списывания
и не доказывает невозможность обхода. Пользовательский код выполняется в VM.
Реальные персональные данные и секреты в репозиторий не входят.

Демонстрационный банк и тестовый решатель поставляются с исходниками:
Backend-задания можно решать по публичному условию. Для реальной аттестации
нужен отдельный закрытый банк; integrity-сигналы не доказывают самостоятельность.

Почтовые поля локального демо принимают только ASCII-адреса `name@example.invalid`.
Реальные домены, включая иностранные и российские, отклоняются самим API
и SMTP-адаптером. Ограничение домена не заменяет правовую проверку способа входа.

Конкурсный выпуск опубликован в открытом репозитории; лицензия проекта не выбрана.
Условия сторонних компонентов,
модели, шрифтов и материалов описаны в [реестре](docs/59-copyright-and-components.md).

Целевой выпуск индивидуального режима — `lct-2026-jury-v3`. Выпуск
`lct-2026-jury-v2` остаётся неизменяемым историческим срезом; опубликованные
в нём общие данные входа не должны использоваться после активации v3.
Актуальный порядок проверки и статус приёмки — в
[порядке сдачи](docs/60-jury-submission.md). Видео и инструкция запуска
остаются резервом. Экранная запись сделана 9 октября и не показывает новый
интерфейс регистрации; её финальная Remotion-вставка пересобрана 11 октября
с актуальной инструкцией индивидуального входа.
