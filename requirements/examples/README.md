# Синтетические наборы и схема

`bank-all-types.json` — полный авторский пример `fsp-bank-v1`: один/несколько
вариантов, число с единицей, открытый ответ с рубрикой, Python/JavaScript/SQL.
`bank-schema.json` — JSON Schema, полученная из действующей серверной Pydantic-схемы.
`bank-simple.csv` — UTF-8/BOM пример простых типов. Эти файлы не содержат ПДн
и не являются официальным банком ФСП или калиброванной сертификацией.

Автор загружает файл в «Конструктор заданий → Импорт материалов → Файл готовых заданий»,
нажимает «Проверить файл», проверяет dry-run,
подтверждает создание черновика и публикует его отдельно. Повторное подтверждение
того же content hash не создаёт копий. Новый файл с прежним external_id создаёт
следующую черновую версию; опубликованная версия и ответы сохраняются.

CSV: обязательны `id,type,title,prompt,skills`. Навыки разделяются `;`, варианты
и ключи записываются JSON в колонках `options` и `answer_key`. Дополнительные
колонки: numeric_answer,absolute_tolerance,relative_tolerance,unit,weight,
partial_credit,bank_title,external_id,specialization,grade,csv_escape. Для открытых ответов
и кода используется JSON или ZIP. Авторский CSV export экранирует формулы
апострофом для безопасного открытия таблицей; импорт не исполняет формулы.
Маркер `csv_escape=apostrophe-v1` позволяет импорту восстановить исходный текст
без потери авторских апострофов. Без маркера содержимое не изменяется.
Мастер позволяет сопоставить названия входных колонок серверным полям и
пропустить лишние колонки. Одно поле нельзя сопоставить двум колонкам.
Сопоставление учитывается в хеше dry-run: исправление соответствий проверяет
тот же файл заново, не возвращая предыдущие ошибки.

ZIP содержит `manifest.json` с той же схемой. Задание кода может заменить
`starter_code` на `starter_file`, указывающий текстовый `.py`, `.js`, `.sql`
или `.txt` внутри пакета. Примеры и скрытые проверки остаются в manifest.
Архив не извлекается на NAS. Запрещены traversal, абсолютные пути, symlink,
дубликаты, шифрование и неизвестные расширения. Лимиты: 2 МБ загрузки,
50 файлов, 4 МБ после распаковки, 100 заданий, глубина JSON 16.

PDF/DOCX служат помощником: извлекается только текст в открытое задание-черновик.
Автор сам задаёт навыки и рубрику. OCR, определение эталонов и угадывание
сложности не выполняются. PDF: до 30 страниц, без шифрования.

Код Python/JavaScript читает stdin и печатает stdout, сравнение игнорирует
конечные пробелы. SQL использует явно указанный SQLite: `setup` создаёт
одноразовую fixture, `output` содержит JSON-массив строк результата. Кандидат
пишет один SELECT; интерфейс не обещает PostgreSQL-диалект. Скрытые проверки
не присутствуют в кандидатском DTO. Авторский экспорт доступен только владельцу.

До 10 скрытых проверок на задачу, до 10 заданий кода в наборе. На попытку
доступны 10 предварительных запусков и резерв для финального исполнения;
суммарно не более 20 jobs. Один предварительный запуск активен одновременно.
VM имеет фиксированные 512 MiB; runtime_limits.memory_mb
показывает этот фиксированный бюджет. API никогда не исполняет код кандидата.
Бюджеты задаются в UTF-8 байтах: код/шаблон 32768, вход 16384, SQL setup 32768,
эталонный вывод 65536. Суммарное JSON-представление скрытых проверок — до
750000 байт, чтобы полный broker payload укладывался в 1 MiB. Сервер
проверяет дополнительные ограничения байтов помимо длины строк JSON Schema.
До окончания ручной проверки/исполнения результат предварительный. Оценка
практики работодателя не меняет подтверждённый грейд профиля.
## Конкурсный рабочий пример

`bank-contest.json` — собственный синтетический набор «Практика Backend:
события, API и данные», 6 задач / 90 минут (ожидаемые бюджеты суммарно 88).
Три задания с кодом, single/multiple-choice и открытый ответ с рубрикой.
Веса — 20/20/20/10/10/20; это авторская модель рабочего примера, не
независимая калибровка Middle. Исходный JSON содержит ключи для автора;
кандидатская API-проекция скрывает ключи и hidden tests.
Набор автоматически добавляется на локальном стенде один раз и также
импортируется через JSON-конструктор. Практика не меняет глобальный грейд.
`./scripts/run.sh contest-bank` проверяет три эталона и три типовые ошибки в VM.
Полный протокол: `docs/contest-bank-results.json`.
