# Разработка

Конкурсный выпуск находится в публичной ветке `main`.
Перед изменением прочитайте [инструкцию запуска](docs/53-self-deployment.md),
[технический отчёт](docs/56-technical-report.md),
[ТЗ и письменные ответы](requirements/README.md) и связанные тесты.

## Рабочий цикл

Создайте отдельную ветку от актуальной рабочей версии. Держите изменения
небольшими и объясняйте решаемую проблему в коммите. Для приложения, миграций,
сборки и проверок используйте Docker Compose через `scripts/run.sh`.
Не пересоздавайте app во время тестов: browser/tools используют его сетевой
namespace. Для одноразовых проверок используйте `--no-deps`.

```bash
./scripts/run.sh test
./scripts/run.sh test-postgres
./scripts/run.sh e2e
./scripts/run.sh contract
./scripts/run.sh api-check
```

Выбирайте проверки по изменению. Для оценки проверяйте повторные формы,
серверные сроки и публичный DTO; для runner — изоляцию VM и практический банк.
Протокол другого commit не подтверждает новую версию автоматически.

## Правила продукта

- Публичный вопрос отдаёт только разрешённые поля. Ответы, объяснения,
  семейства и параметры остаются на сервере.
- Пользовательский код запускается через runner в одноразовой VM.
  API не получает Docker socket или доступ к файлам хоста.
- Практика работодателя и ИИ-подсказка не повышают глобальный грейд.
  Опубликованная версия банка и сохранённые баллы не перезаписываются.
- Официальный API ФСП не выдумывается. Mock обозначается отдельно;
  чужой OIDC client не используется.
- В Git входят синтетические данные. `.env`, модели, секреты,
  оригиналы с персональными данными и локальные архивы остаются вне Git.

## Документы и публикация

Документация и пользовательские пояснения пишутся на русском языке.
Существенные изменения архитектуры объясняются в техническом отчёте
и матрице требований. Синтетические тесты не называются независимой
калибровкой, юридической сертификацией или доказательством качества найма.
Лицензии и записи происхождения материалов сохраняются.

Состав PDF/Word задаётся в `docs/document-set.json`. После изменения
источников выполните `./scripts/run.sh report`, проверьте ссылки и артефакты.
Обновите README, CHANGELOG и связанные требования.

Перед публикацией просмотрите diff и состав коммита. Не включайте секреты,
веса, `local-data/`, локальные инструкции среды и `.github/workflows/`.
GitHub CI/CD по решению владельца не публикуется; проверки выполняются локально.
Не используйте force push и команды, теряющие незакоммиченную работу.
Проектная лицензия не выбрана; внешний доступ предоставляет владелец.
