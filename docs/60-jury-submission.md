# 60. Ссылки и порядок сдачи решения

Команда — «Студия 37». Очищенный конкурсный выпуск публикуется в открытом
`punkpsyh-hash/Fsp`, ветка `main`, тег `lct-2026-jury-v2`. Код, документация, презентация
и видео скачиваются без аккаунта GitHub и приглашения. Полная прежняя история
сохраняется в закрытом `Fsp-private-history`; полный сторонний брендбук в
публичный снимок не входит.

ТЗ не задаёт открытую или закрытую видимость: в § 5.2 требуется ссылка на код.
Владелец разрешил публичный очищенный выпуск 11 октября 2026 года.
Форма конкурса и письма поддержки автоматически не отправляются.

## Доступ жюри к демо

Откройте [https://fsptest.kolesnikovny.ru](https://fsptest.kolesnikovny.ru).
Отдельного окна Basic Auth и внешнего пароля больше нет. На странице входа
введите демонстрационную почту и общий пароль тестовых аккаунтов:

| Роль | Демонстрационная почта |
|---|---|
| Кандидат | `demo-candidate-a@example.invalid` |
| Работодатель | `demo-employer-x@example.invalid` |

Пароль обоих тестовых аккаунтов:

`LhqDLeyL_qtmcp5JlAzfZlotXmpXUUyT58ohEJewKDZx0poylO83YWn7tx2ejJIt`

Нажмите «Войти с паролем». Для смены роли выйдите из аккаунта и войдите с другим
адресом из таблицы. Адреса синтетические: получать письмо не требуется.
Это общие демонстрационные аккаунты; введённые тестовые изменения могут видеть
другие проверяющие. Используйте только вымышленные данные.

Владелец разрешил снять внешний пароль и опубликовать эти данные входа
11 октября 2026 года, поскольку отдельная передача жюри невозможна.
Пароли NAS, VPS, базы данных, SSH-ключи и runner token сюда не относятся.

## Временный домен

Временный стенд доступен по адресу `https://fsptest.kolesnikovny.ru` через
отдельный nginx vhost российского VPS ru2 и зашифрованный обратный SSH-туннель
к NAS в России. Размещение в России подтверждено владельцем; это не вывод
по GeoIP. На 11 октября 2026 года внешний клиент с компьютера владельца
прошёл 22 HTTP-проверки с обычной проверкой доверия TLS: политика с фактическим
оператором, прежний Basic Auth, парольный вход кандидата и работодателя, Secure/HttpOnly
cookie, CSRF и выход, экспорт синтетического профиля, запрет регистрации,
загрузки резюме и mock-входа ФСП. Протокол —
`docs/release/2026-10-11-legal-submission/jury-public-http.json`.

[Конфигурация и запуск](61-temporary-domain-stand.md) используют отдельный
проект и базу с синтетическими аккаунтами. Вход в приложение сохраняется;
внешний Basic Auth снят отдельным override `compose.jury-public-demo.yaml`. Почта, регистрация, вход по коду,
mock-вход ФСП и загрузка PDF в показе жюри отключены. Полный путь регистрации и
ФСП mock проверяется локально по инструкции; видео показывает регистрацию
кандидата через mock-почту, но не внешний API ФСП. Временный
синтетический стенд не предназначен для реальных соискателей. Базовые задания
доступны без LLM; публичный jury-показ не подключает модель. Локальный полный
стенд и универсальный коннектор Qwen описаны в инструкции развёртывания.

[Видео с пояснениями, главами и схемами](https://github.com/punkpsyh-hash/Fsp/releases/download/lct-2026-jury-v2/demo-explained.mp4)
и инструкция самостоятельного запуска остаются резервом. Финальная вставка
видео содержит прежнее указание передать пароль отдельно; актуальные данные
входа приведены выше. Новая внешняя проверка без Basic Auth —
`docs/release/2026-10-11-jury-v2/public-demo-http.json`.
Текущая доступность не гарантирует её весь срок оценки: владелец контролирует
питание NAS, VPS и домен до окончания проверки.

Содержание ролика и таймкоды — [пояснения к видео](62-video-guide.md).
Получение открытого выпуска и порядок запуска —
[инструкция GitHub](63-jury-github-access.md).

## Основание в требованиях

ТЗ, раздел 5.2, страницы 7–8: доступны репозиторий, презентация,
сопроводительная документация DOC/PDF; развёрнутый прототип крайне желателен.
При невозможности размещения допускаются видео работы и инструкция запуска.
Письменный ответ E10 допускает видео вместо живого стенда, отводит 10 минут
на выступление и рекомендует держать стенд весь срок оценки. Если срок
невозможно выдержать, его согласуют с организаторами отдельно.

Проверяющему достаточно Docker, Compose, Bash и доступа GitHub; установка
Python/Node на хосте и загрузка модели для основного сценария не нужны.
Локальная Qwen скачивается из официального репозитория Hugging Face на
закреплённой ревизии с проверкой SHA-256; веса не входят в GitHub проекта.
