Тема: Условия подключения конкурсного проекта «Карьерный профиль» к ФСП ID и API достижений

Здравствуйте!

Готовим конкурсный проект обратного подбора ИТ-специалистов для специального
трека ФСП ЛЦТ 2026. Развёрнут рабочий Docker-стенд на закрытом NAS:
React/TypeScript, FastAPI, PostgreSQL; используются только синтетические данные.
Интеграция достижений сейчас явно обозначена как локальный mock.

В §4 ТЗ указано, что API, данные реестра и структура не предоставляются в рамках
хакатона. В публичном кабинете спортсмена обнаружен вход через ФСП ID,
а discovery `https://sso.fsp-russia.ru/realms/fsp/.well-known/openid-configuration`
объявляет OIDC Authorization Code и PKCE S256. Защищённые операции мы не вызывали.

Просим уточнить, доступна ли сейчас разрешённая интеграция для нашей команды
либо после конкурса, и предоставить соответствующий технический контакт.

1. **ФСП ID отдельно от реестра:** возможна ли регистрация собственного client,
   есть ли тестовый realm/аккаунты, какие flow, scopes и методы client authentication
   разрешены? Какие точные redirect/logout URI можно зарегистрировать для
   закрытого тестового NAS с SSH-туннелем и будущего HTTPS-стенда?
2. **Официальный API достижений:** есть ли разрешённый read-only sandbox;
   base URL, versioned OpenAPI/схема, синтетические примеры и формат ошибок?
   Как identity `(issuer, subject)` сопоставляется с ID спортсмена; как проверяется
   доступ только к собственным данным? Нужен ли отдельный audience/service client?
3. **Контракт данных:** устойчивые ID событий/участников, командная роль,
   дисциплина, место/баллы, статус подтверждения; версии, исправления и отзыв
   результата, пагинация, incremental sync, лимиты и Retry-After. Какие сведения
   официально допустимо считать подтверждённым достижением?
4. **Условия использования:** какие операции/поля разрешены, как оформляется
   согласие спортсмена на импорт и отдельный показ работодателю; ограничения
   хранения, публикации, экспорта, удаления и отзыва доступа? Какие требования
   предъявляются к приложению до обработки реальных данных?
5. **Приёмка и поддержка:** документация с датой/версией, тестовые сценарии,
   срок и порядок выдачи доступа, контакт при изменениях контракта.

Если доступ пока не предусмотрен, просим подтвердить сохранение mock-сценария
для конкурса и желаемые требования совместимости на будущее.

Секреты просим передавать только согласованным защищённым каналом после
регистрации нашего приложения; не в публичных документах, репозитории или
обычном ответе с открытой копией адресатов. Чужой client кабинета не используем.

Спасибо!
