# 53. Развёртывание проверяющими на своём компьютере

Это инструкция для нового компьютера, без NAS владельца, его SSH-подключений,
локальных весов или Python/Node на хосте. Код скачивается из открытого GitHub,
базовая Qwen — из официального Hugging Face. Обучение для запуска не требуется:
адаптеры v1/v2 отклонены, используется исходная модель без адаптера.

## Выбор режима

| Режим | Что требуется | Что работает |
|---|---|---|
| Без ИИ | Docker, Compose, Git Bash/Bash | Профиль, оценки, подбор, приглашения, конструктор, задания в VM |
| Полный стенд с Qwen | NVIDIA GPU; модель скачивается командой ниже | Также четыре типа ИИ-черновиков и предложение оценки ответа |
| Свой сервер модели | Доступный OpenAI-совместимый API с JSON Schema | Те же ИИ-функции после проверки совместимости |

Локальный стенд использует синтетические данные и mock ФСП; реальные данные
людей вводить нельзя. Результат ИИ проверяет и подтверждает автор задания.

## 1. Подготовка компьютера и получение кода

Нужны Git, Docker Engine с Compose **2.24.4 или новее** и Bash. Образы
поставляются для Linux x86-64; Apple Silicon/AMD GPU как полный GPU-стенд
этого выпуска не проверены — используйте свой совместимый сервер модели.
На Windows используйте Docker Desktop в режиме Linux containers / WSL2 и
Git Bash. Python, Node и PostgreSQL устанавливаются внутри образов.
Для базового стенда рекомендуются 4 CPU, 8 ГБ RAM и 15 ГБ свободного диска.
Для GPU-стенда рекомендуются NVIDIA с 8 ГБ VRAM, 24 ГБ RAM и 40 ГБ диска
для весов, образов и кэшей; измерения выполнены на RTX 4070 Laptop 8 ГБ.
6 ГБ VRAM — нижняя граница конфигурации, а не проверенная гарантия на любой GPU.

Репозиторий открытый: для скачивания аккаунт GitHub и приглашение не нужны.
Учётные данные владельца передавать не нужно. Команды для **Bash**:

```bash
git clone \
  --branch main \
  --single-branch \
  https://github.com/punkpsyh-hash/Fsp.git \
  fsp
cd fsp
docker version
docker compose version
```

В Git Bash на Windows перед дальнейшими командами:

```bash
export MSYS_NO_PATHCONV=1
export COMPOSE_PATH_SEPARATOR=:
```

Клонировать на компьютере владельца следует на диск D. На компьютере
проверяющих выберите диск с достаточным свободным местом. Все новые веса
записываются в каталог проекта; GPU-кэши Compose — в Docker volumes.
Первая сборка требует доступа к Docker Hub, npm и PyPI/PyTorch; загрузка
модели — к Hugging Face и его хранилищу файлов. После скачивания модель
работает offline. Не запускайте одновременно разные копии с именем Compose `fsp`.

## 2. Проверить базовый стенд

```bash
./scripts/run.sh start
./scripts/run.sh check
```

Откройте `http://127.0.0.1:8470`, API — `http://127.0.0.1:8470/api/docs`.
`check` показывает состояние контейнеров, проверяет API и запрос к БД.
`llm_provider: none` означает ожидаемый режим без ИИ.
На странице входа выберите синтетический аккаунт кандидата или работодателя.

Начальный экран показан на [[figure:landing]]. На работающем стенде используется
тот же интерфейс выбора демонстрационного кабинета. Данные на снимке синтетические.

<!-- figure:landing -->

После входа работодателя откройте «Конструктор заданий»; перечень наборов показан
на [[figure:question-bank]]. Проверка этого экрана не означает проверку качества
ответов модели: генерация и подтверждение автором выполняются отдельными действиями.

<!-- figure:question-bank -->
У работодателя проверьте подбор, банк заданий и приглашение; у кандидата —
профиль, тест, добровольное практическое задание и принятие приглашения.
До согласия кандидата контакты работодателю недоступны.

Скрипт создаёт `.env` со случайными секретами, сохраняет прежние значения,
применяет миграции и идемпотентный seed. **Не копируйте `.env.example` поверх
созданного `.env`.** Если `/dev/kvm` недоступен, автоматически используется
медленный TCG; пользовательский код всё равно выполняется в отдельной VM.

## 3. Скачать и включить локальную Qwen

Для Linux нужен настроенный [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
Для Docker Desktop GPU должен быть доступен Linux-контейнерам через WSL2.
Проверьте это до многочасовой сборки:

```bash
docker run --rm --gpus all ubuntu:24.04 nvidia-smi
./scripts/run.sh model-fetch
./scripts/run.sh model-verify
./scripts/run.sh start-llm
```

Загрузчик получает около 8 ГБ весов из
[официального репозитория Qwen](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/tree/cdbee75f17c01a7cc42f958dc650907174af0554).
Версия закреплена полным коммитом `cdbee75f17c01a7cc42f958dc650907174af0554`;
SHA-256 каждого файла — в `ml/release/model-serving-v3-manifest.json`.
GitHub содержит загрузчик и manifest, а не многогигабайтные веса.
Модель опубликована авторами под Apache-2.0; её `LICENSE` загружается вместе
с весами. Это не выбирает лицензию самого проекта.

При обрыве повторите `model-fetch`: проверенные файлы будут пропущены,
незавершённый файл скачивается заново. `model-verify` сверяет хеши offline,
не загружает модель в GPU и завершится с ошибкой при пропуске, изменении или
лишнем файле. Каталог весов — `ml/models/qwen3-4b-instruct-2507-serving-v3/`.
Не кладите туда свои заметки, адаптеры или другой tokenizer.

`start-llm` сначала проверяет файлы, собирает образы и ждёт готовности.
Ключ локальной модели создаётся автоматически в `.env`; модель и приложение
получают одинаковый ключ. Сервис выполняет обязательный warmup до `healthy`.
Модель не публикует порт на хост; сеть `llm_net` внутренняя, веса read-only.
Прогрев проверенного образа занял около 203 секунд; первый download/build
может занять значительно дольше и не входит в эти 203 секунды.

Для последующих команд в **каждом новом Bash-терминале** выберите тот же набор:

```bash
export COMPOSE_FILE=compose.yaml:compose.llm.yaml
./scripts/run.sh check-llm
./scripts/run.sh status-llm
```

На Windows скрипт автоматически добавит TCG overlay. Ожидается `healthy` у
`db`, `app`, `runner`, `model`, а в выводе `check` — `local_model: ready`.
Проверка подтверждает модель, её версию и ключ, но не правильность нового задания.
Для проверки генерации войдите работодателем, откройте «Банки заданий» /
конструктор, запросите по одному заданию single, multiple, numeric, open.
Автор проверяет условие, эталон, варианты и рубрику перед сохранением и публикацией.
Подсказка ИИ по ответу тоже требует ручного решения; практическое задание
не повышает глобальный грейд. Проверенный путь и ограничения — [приёмка](48-release-acceptance.md).

## 4. Подключить свой сервер через существующий коннектор

Вместо `compose.llm.yaml` можно использовать реализованный
`OpenAICompatible` в `src/server/llm.py`: это административная настройка,
а не поле URL, доступное пользователю. Поддерживается
`POST <base_url>/chat/completions` с Bearer-ключом, `messages`, `max_tokens`,
`response_format.type=json_schema`, строгой схемой и `finish_reason=stop`.
Обычного текстового chat API для генератора недостаточно.

После `./scripts/run.sh init` отредактируйте **только указанные строки** `.env`,
сохранив сгенерированные `FSP_DB_PASSWORD`, `FSP_RUNNER_TOKEN` и остальные настройки:

```dotenv
FSP_LLM_PROVIDER=openai-compatible
FSP_LLM_BASE_URL=https://your-model-server.example/v1
FSP_LLM_MODEL=your-model-id
FSP_LLM_API_KEY=your-own-local-key
FSP_LLM_TIMEOUT=100
FSP_LLM_GENERATION_TIMEOUT=120
```

Значения выше — пример, адрес `.example` не является рабочим сервером.
Укажите адрес, доступный **из контейнера app**. Внешний сервер требует HTTPS;
внутренний локальный сервис допускает HTTP. `localhost` внутри app означает
сам контейнер, а не компьютер с моделью. Для Docker Desktop используйте
`host.docker.internal`, если модель слушает доступный контейнерам адрес.
Обращение к уже работающему локальному серверу не устанавливает ему модель.
При сетевом доступе ключ и настройки TLS задаются администратором.

```bash
unset COMPOSE_FILE
./scripts/run.sh start
./scripts/run.sh check
```

В этом режиме `check` проверяет конфигурацию и базовый стенд; он **не делает
платный запрос** и не объявляет произвольную модель совместимой.
Совместимость проверяется четырьмя заданиями в конструкторе и подсказкой оценки.
Собственная Qwen на GPU проверена; произвольные внешние провайдеры отдельно
не сертифицированы. Не передавайте реальные персональные данные в модель.
Если ранее включали Compose-модель, сначала остановите её по пункту 5, затем
переключите конфигурацию; `unset COMPOSE_FILE` само не останавливает контейнер.

## 5. Эксплуатация и типовые проблемы

Для GPU-режима сохраняйте `COMPOSE_FILE=compose.yaml:compose.llm.yaml`:

```bash
./scripts/run.sh logs
./scripts/run.sh model-report
./scripts/run.sh backup
./scripts/run.sh stop-llm
./scripts/run.sh start-llm
```

`stop-llm` останавливает выбранный проект, включая модель, и сохраняет БД и кэши.
`backup` сохраняет dump в игнорируемый каталог `backups/`; инструкции по
восстановлению — [эксплуатация](44-deployment-and-operations.md).
Не используйте `down -v` или глобальный Docker prune для обычного перезапуска.

| Симптом | Что проверить |
|---|---|
| GitHub 404 / authentication failed | Верно ли указан публичный адрес `https://github.com/punkpsyh-hash/Fsp`; исправны ли DNS и соединение с GitHub |
| Compose не понимает `!override` / `!reset` | Обновить Compose до 2.24.4+ |
| Порт 8470/15432 занят | Остановить свою прежнюю копию; не останавливать чужие сервисы |
| GPU недоступна | `nvidia-smi`, Container Toolkit / WSL2, режим Linux containers |
| SHA-256 / недостающий файл | Повторить `model-fetch`, затем `model-verify`; не менять manifest |
| Model unhealthy / CUDA OOM | Освободить свою GPU-нагрузку, проверить VRAM; не включать CPU-offload обходом |
| `check` отклоняет ключ | Сверить конфигурацию `.env`, пересоздать model/app штатным `start-llm` |
| Задание не сгенерировано | Посмотреть машинную причину в UI; timeout/ошибка схемы не означают публикацию |
| Медленное практическое задание | Проверить KVM; TCG сохраняет VM-границу, но работает медленнее |
| Docker Desktop не стартует | [Диагностика Docker Desktop](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/) |

Дополнительная регрессия: `./scripts/run.sh test`, `test-postgres`, `e2e`,
`runner-test`, `contest-bank`. Эти команды могут занять десятки минут.
Протокол именно этой доработки публикуется отдельно от исторической приёмки.

Если Docker сообщает `all predefined address pools have been fully subnetted`,
его автоматические диапазоны исчерпаны другими сетями. Не удаляйте чужие сети.
Администратор может задать свободные, не пересекающиеся с LAN/VPN/Docker
подсети в локальном Compose overlay; [проверенный пример](54-self-deployment-acceptance.md)
использует этот способ. Диапазоны в примере нельзя переносить без проверки
сети конкретного компьютера.

## Приёмка этой инструкции

Для временного показа на собственном домене используйте отдельную
[инструкцию NAS и jury-контура](61-temporary-domain-stand.md). Это парольное
демо на синтетических аккаунтах с отключёнными регистрацией, письмами и импортом
резюме; базовый локальный режим сохраняет полный регистрационный путь.
Публичный запуск требует действительных сведений владельца и email в политике,
DNS, HTTPS и отдельной внешней приёмки. Название «тестовый стенд» не заменяет эти
условия. Внешняя почта по умолчанию выключена; одного `FSP_SMTP_HOST` недостаточно:
нужно явное `FSP_SMTP_ENABLED=1`, TLS и проверка условий поставщика по docs/58.

Проверяем: получение кода без локальных весов/секретов; создание `.env` и
повтор без перезаписи; запуск БД/API/runner из чистого дерева; download и
offline SHA-256; отказ при повреждении; состав Compose с GPU и без GPU;
работа коннектора на контрактных тестах; отсутствие закрытых данных и CI/CD
в публикуемом дереве. Результаты и точный срез —
[docs/54](54-self-deployment-acceptance.md).
